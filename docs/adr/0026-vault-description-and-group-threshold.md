# vault 说明 + 抬高新建组门槛

vault 要对人和 agent 可导航：配置源与 env/text 分组带一份共用的**说明**；env/text 禁止隐式建组，新建组必须显式且必填说明。组保持扁平、按类型分桶，不做真树；闸门不推广到 Host/KeyPair/LLM/MCP。

env 组同时承担「同名变量换哪一套值」和「侧栏分类」；用组给裸名隔服务会把一级组撑爆。组名只承载变体维度（个人/工作/项目），服务与机器名下沉到 key 前缀。

## 决策

1. **说明**是人和 agent 读的同一段短纯文本（约 2KB、无 Markdown、不准写密钥），随 vault 同步。贴在全部配置源（env/text/config 条目、Host、KeyPair、LLM Provider 档案、MCP Server 档案）以及 env/text 分组上。config 与 MCP 档案已有该字段则对齐规则，不另开字段。LLM 说明只在 Provider 档案上，不复用模型目录文案。本机状态（当前指向、导出状态）不贴说明。存量不强制回填；list 必带说明。
2. **env/text 写得贵**：`set` 不再在组不存在时自动建组；新建组（CLI/TUI/MCP）必填说明。MCP 仍可 `group add`。组名约定只写进 agent skill，软件不校验前缀。
3. **两种用法，仍是一个 Group**：
   - **变体组**：装外部工具按名读的契约 key，同名不同值，靠 activate 切换；数量 = 场景数。
   - **存档组**：装带服务/机器前缀的自用 key，默认不激活；不再为每个服务开 `svc-<名>`。
   软件暂不立组类型。外部契约名保持裸名（改名前缀会让 SDK/compose 找不到）；自用名才加前缀、合并进存档组。同一服务多台机器、脚本要同时看见两套密码时，机器名写在 key 前缀里（`LNV_` / `MSABJ_`），不按机器拆组。`device-*` 只留给互斥的「激活哪台就用哪套身份」。
4. **同名冲突可见**：`env export` 与 `group activate` 对已激活组之间的同名 key 打 warning（列出组名与谁覆盖谁），不阻断。`default` 兜底覆盖是合法用法，硬失败会误伤。
5. **明确的不**：不引入嵌套组；Host/KeyPair 组不升格为独立登记；LLM/MCP 继续用别名、不造组；Host/LLM/MCP 的 MCP 工具保持只读，这三类说明由 CLI/TUI 写；敏感/工作标记与分 vault 先不做。

## Considered Options

- **嵌套组 / 真树**：会把「激活 `infra` 是否包含 `infra/ali/oss`」变成新的领域问题；层级用 key 前缀表达，不改寻址。
- **组 = 项目归属、svc-* 收成一个 `svc`**：忽略了外部契约名必须靠激活切值，个人/工作同名变量会失去切换面。
- **组上立变体/存档类型**：要再引入互斥维度，证据还不够；先用约定跑。
- **Host 组一等公民化**：Host 组实际只有组织/项目桶，膨胀在 env/text。
- **MCP 禁止建组**：真该新开一组时 agent 只能停工；必填说明已足够贵。
- **软件强制前缀 / 全部 key 加前缀**：前者误伤已有合法组名；后者破坏外部工具约定名，还要新造运行时别名投影。
- **同名静默覆盖**：变体组同时激活时，人以为在用个人账号、实际可能是工作账号。
- **agent-only 第二字段 / 把说明写进 text 值**：前者必腐，后者和密钥混在一起、list 也带不出来。
