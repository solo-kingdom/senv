# Design: tui-ux-multiselect

## Context

组件（③）已冻结游标/窗口最小面；本 change 在其上叠加选择集。语义细节全部来自 grill D9，无新决策面。

## Goals / Non-Goals

**Goals:** 五类列表（env vars/text blocks/ssh hosts+keypairs/config items/mcp servers）多选与批量动词；AI 向导不动。

**Non-Goals:** visual mode、跨栏选择、选择集持久化到磁盘（会话内存态）、scope 快捷键退役。

## Decisions

- **选择集以稳定标识为键**：`map[string]bool`，键为条目唯一标识（`group/key`、alias 等），不用行号——过滤与重载后选择不漂移。条目被删除后残留键在提交时按「不存在即跳过」处理并计入汇总提示。
- **批量动词复用单项键**：`d`/`x`/`i`/`u` 在选择集非空时作用于选择集，为空回落游标——不新增批量专用键，键位表零增量。`t`（env 组激活/停用）作用于组侧栏选择语境，不参与条目选择集（组与条目不同栏，天然不混）。
- **计划流批量化 = 复用现有 plan 数据结构**：config `i`/`u` 与 MCP 导出/撤回的 plan 本就是多条目列表，批量只是把范围从「单条/整组」换成「选择集」，计划页/`F` 覆盖/逐条确认逻辑不变。env/text/ssh 的 `d`/`x` 无 plan 流，批量时合并为一次确认（列出全部目标），`x` 导出走既有路径表单（多目标时要求目录或逐条生成文件名——采用逐条沿用现有命名规则、写同一目录，确认页列出生成路径清单）。
- **状态栏计数**：`已选 N（M 项被过滤隐藏）`，N=0 不显示；批量提交成功后清空选择集并刷新。

## 数据流与错误处理

选择集是会话内存态；批量执行复用各 Manager 既有单条接口逐条调用（与 MCP `X`「单个失败不中止其余」一致），结束汇总成功/失败数，失败走统一提示条。不新增并发写。

## Risks / Trade-offs

- [批量删除误操作面变大] → 所有批量写必经确认（一次确认列全部目标或逐条确认），无免确认路径
- [ssh `x` 导出多目标命名歧义] → 确认页显式列出每个生成路径后执行；重名冲突时单条报错不中止其余
